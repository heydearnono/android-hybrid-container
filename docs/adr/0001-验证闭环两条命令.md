# ADR-0001 · 验证闭环由两条命令组成，各管一半

- 日期：2026-09-18
- 状态：已采纳

## 背景

本仓全部由 AI 开发，而这台机器上**没有真机、没有 AVD、没有 `cmdline-tools`、没有任何 system-image**，
`minSdk = 37` 还要求 API 37 的镜像。于是「改完怎么算验证过」这件事从一开始就是分裂的：一半能自动跑，
另一半只有人在设备前才做得到。

更要紧的是 WebView 这一层**测不了却会假绿**：JVM 单测里 `android.webkit` / `androidx.webkit` 来自
`android.jar` 的 stub。不开 `testOptions.unitTests.isReturnDefaultValues` 则 stub 方法抛「not mocked」，
开了则静默返回默认值——后者会让断言 `WebSettings` 取值、断言 `WebViewClient` 回调效果的测试全部变绿，
而那个绿与代码无关。假绿比没有测试更坏，所以本仓**刻意没开**那个开关（`AndroidConfig.kt`）。

## 决定

验证闭环是**两条命令**，谁也不假装能替另一条：

- `./scripts/check.sh`（`spotlessCheck` → `assembleDebug` → `test` → `lint`）——AI 能跑的全部。绿的定义：
  格式无 diff、APK 产出、单测全过、lint 零 error
- `./scripts/probe.sh`（装 → 清日志 → 起 → **人工按** → 回读 logcat → 固定十六行）——只有人在设备前
  才能跑的那一半。它**不代按**

两条都不覆盖的事，写进 `TASKS.md` 标「待模拟器核实」或「只剩走查」，**不写「已验证」**。

## 理由

- 合成一条不行：`probe.sh` 依赖人工按按钮、依赖设备，放进 `check.sh` 会让 CI 与本地都跑不过，
  最后的结果是这条被注释掉
- `probe.sh` 里代按（`adb shell input tap`）看着方便，但坐标一变就点在别处，而它**照样会打出 PASS**
  ——那是最坏的一种绿。按钮由人按，命令只负责回读
- 不设「第三种验证」（截图比对、instrumented 测试）：前者在这台机器上跑不了，后者同样要设备，
  加进来只是把「没验证」这件事藏得更深

## 后果

- 每一条容器行为都能指到自己的判据：要么某条单测，要么十六行里的某一行，要么 `TASKS.md` 里一句
  「未核实」。**没有第四种状态**
- 代价是「已落地」在本仓不等于「过了」。读 `TASKS.md` 必须先读状态记号那张表
- 想推翻这个结构，得先解决「设备侧结果怎么不靠人也能拿到」——那是 CI 上挂模拟器的事，
  与本仓当前的环境事实（连 `sdkmanager` 都没有）差得远
