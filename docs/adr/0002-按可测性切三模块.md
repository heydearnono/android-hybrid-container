# ADR-0002 · 按「能否在 JVM 上测」切模块，不按惯例切

- 日期：2026-09-18
- 状态：已采纳

## 背景

容器这一层的代码只有两类：**判定**（这一跳放不放、这行日志打什么、失败要不要进错误态、能不能再换一次
WebView）与**动作**（往 `WebSettings` 上写字段、`handler.cancel()`、`request.deny()`、`webView.destroy()`）。

判定写错了后果重（漏一个跨 origin 就把页面送出去了），而它恰好全部是纯逻辑；动作写错了后果也重，
但它碰的是框架对象，在 JVM 单测里**只能得到假绿**（见 [ADR-0001](0001-验证闭环两条命令.md)）。

## 决定

三个模块，按「能否在 JVM 上测」划线：

| 模块 | 装什么 | 测试 |
| --- | --- | --- |
| `:core:container` | 纯 JVM。**全部判定**：`HostingOrigin` / `AssetRouting` / `NavigationGate` / `CrabLog` / `ContainerStateMachine` / `RenderProcessRecovery` / `ContainerCoordinator` / `WebSettingsSpec` / `DocumentStartScript` / `UserAgent` / `RemoteDebugging` | 全部有单测 |
| `:core:webview` | 碰 `android.webkit` 的部分，**只许直线代码**：把回调原样转进来、把返回值原样转回去 | **刻意不带单测** |
| `:app` | Compose 壳、生命周期、探针页素材、扫源码树的接线检查 | 只测扫得动的那些 |

`:core:webview` 对 `:core:container` 用 `api`：公开签名里出现了它的类型，`implementation` 会让 `:app`
报 `Cannot access … which is a supertype of …`（本仓踩过）。

## 理由

- 反过来（把判定留在 `WebViewClient` 里）也能跑，但那些代码就永远没有判据。M4 里最容易错的三处
  ——`onReceivedError` 早于 `onPageFinished`、`onRenderProcessGone` 返回 false 会杀进程、`JsResult`
  必须回一次——全是回调时序问题，正好是最需要测试的地方
- 也考虑过给 `:core:webview` 配 Robolectric：那能让一部分回调跑起来，但 WebView 在 Robolectric 下是
  影子对象，`WebSettings` 的取值同样是假的，等于把假绿换了个更贵的形式
- 「不带单测」是硬约束，不是暂缺。所以那个模块里**不许出现分支与状态**：一旦出现，它就成了没有判据的
  逻辑。目前唯一的分支是 `documentStartScriptSupported` 那个布尔，它的两条路各自都是直线

## 后果

- 判定改一行就有测试兜着；动作改一行只能靠观察，于是它们被逼得极薄（`CrabWebViewClient` 十个 override
  没有一个 `if`）
- 代价是多了一层转发：一个回调要经 `:core:webview` → `ContainerCoordinator` → `ContainerActions` 三跳。
  读起来绕，写的时候也容易想「就在这里判一下算了」——那正是这条 ADR 要挡住的
- 想在 `:core:webview` 里写判定，先解决「它怎么被测」。答案不能是 Robolectric（见上）
