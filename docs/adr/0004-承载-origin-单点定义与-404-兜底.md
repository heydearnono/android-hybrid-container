# ADR-0004 · 承载 origin 单点定义，承载路径未命中一律 404

- 日期：2026-09-18
- 状态：已采纳

## 背景

承载 origin（`https://and.crab.invalid`）在容器里被三处用到：`WebViewAssetLoader.setDomain` 的拦截范围、
`addDocumentStartJavaScript` 的注入 origin 规则、导航闸门的放行判据。**这三处必须说的是同一件事**——
拦截范围比注入范围大一点，页面就能拿到一个没注入的 origin；闸门比拦截范围大一点，就有请求能真的发出去。

`WebViewAssetLoader` 这边还有一处形状上的坑（javap 读 `androidx.webkit` 1.17.0 的实现核过）：
`PathHandler` 未命中时返回 null 的含义是「交回 WebView 默认处理」，而默认处理就是**真的去联网**。
承载 origin 落在 RFC 6761 保留的 `.invalid` 之下，那个请求注定失败，但失败之前它已经出去了。

## 决定

两条：

1. **字符串 `and.crab.invalid` 全仓只在 `HostingOrigin.kt` 出现一次。** 其余全部从它派生。一条扫源码树的
   单测（`HostingOriginSingleDefinitionTest`）盯着这件事——字面量取自 `HostingOrigin` 自身，断言除定义处
   之外零命中。唯一的例外是探针页 `probe.js` 里那个**期望值**（页面要拿它比 `location.origin`），
   例外写在测试里，不是走查约定
2. **承载 origin 上的一切都由 `AssetRouting.resolve` 判，未命中一律由容器自己回 404 + `INTERCEPTED`。**
   只注册一个 `/` 前缀的 `PathHandler`，`handle()` **永不返回 null**

## 理由

- 「三处必须同源」靠人对齐，等于把安全边界押在记性上。它又恰好是能被一条测试管住的事——那就管住它
- 只注册一个 `/` 前缀，是为了不依赖 `PathMatcher` 的匹配顺序：注册多个前缀时「哪个先命中」是
  `WebViewAssetLoader` 内部的事，而漏出去的表现（请求真的发到网上）在设备上看不出来
- 路径判定放在纯 JVM 侧（`AssetRouting`）而不是 `PathHandler` 里：穿越判错等于把整个 assets 目录漏出去，
  这种代码必须有单测（见 [ADR-0002](0002-按可测性切三模块.md)）
- `..` 不做「弹栈」化解（`a/../b` 不折成 `b`），想穿越就判越界。少一次抵消的机会，代价只是素材路径里
  不能写 `..`

## 后果

- 改承载 origin 只改一个文件；漏改一处会红在单测上，不用等到设备上
- 探针页里那个期望值是**第二份拷贝**，编译器管不到它。`.html` / `.js` 不在 Spotless、lint、编译器的
  覆盖范围里，那条扫文本的单测是唯一的兜底（见 [ADR-0005](0005-运行记录只有探针页一种形式.md)）
- 代价：素材文件名里不能带字面量 `%`（路径要反复百分号解码到不变，才能挡住 `%252e%252e%252f` 这类
  双重编码）
- 想给容器加一个「从网上加载」的口子，先解决「怎么把它与漏出去区分开」——目前的判据是
  「承载 origin 上一个真实网络请求都没有」，加了口子这条判据就没了
